# 代码审查报告

## 一、问题描述与优化建议

-【中】[FusionAlgoInstanceController.java: benchmarkFetchTdbAsync/约行 190-199]  
  代码直接对 `Map<String,Object> params` 做强制类型转换：`List<String> instanceIds = (List<String>) params.get("instanceIds");`、`String startTime = (String) params.get("startTime");`、`Boolean mergePoints = params.get("mergePoints") != null ? (Boolean) params.get("mergePoints") : true;`。  
  - **影响**：当前端传入 `instanceIds` 为非 List、`startTime` 为非 String、`mergePoints` 为字符串 `"false"` 等时，会触发 `ClassCastException`，接口直接返回 500，健壮性差。  
  - **建议**：新增请求 DTO，并配合 `@Validated` 校验参数；或在控制层安全拆解、校验类型后再调用 Service。

-【中】[FusionAlgoInstanceServiceImpl.java: benchmarkFetchTdbDataAsync/约行 1790-1810]  
  对 `instanceIds` 仅执行 `stream().distinct().collect(Collectors.toList())`，未过滤 null，也未限制数量；后续对每个 `mergedSqlList` 元素都创建 `CompletableFuture`。  
  - **影响**：恶意或异常请求可传入超大实例 ID 列表，导致大量点位查询、SQL 提取以及大量异步任务无上限下发给 `ForkJoinPool.commonPool()`，容易引发资源耗尽和线程池饥饿。  
  - **建议**：增加最大实例数、最大点位数限制，过滤 null 元素，超过阈值时抛出业务异常或分批执行。

-【中】[FusionAlgoInstanceServiceImpl.java: benchmarkFetchTdbDataAsync/约行 1792-1805]  
  解析时间字符串失败时仅 `log.warn("解析压测时间失败", e);`，`startSec`、`endSec` 保持为 0，后续仍会继续执行取数。  
  - **影响**：会被替换为 `0` 作为时间戳传入 SQL，可能查询异常时间范围甚至造成全量扫描，压测结果完全失真，增加 TDB 压力。  
  - **建议**：解析失败直接抛出 `ServiceException` 或终止压测，不允许以默认值继续执行。

-【中】[FusionAlgoInstanceServiceImpl.java: benchmarkFetchTdbDataAsync/约行 1818-1822]  
  代码中写死默认数据源：`if (datasourceId == null) { datasourceId = 1L; }`。  
  - **影响**：当点位表和 extractionSql 均未提供 `datasource_id` 时，会错误地查询 ID=1 的数据源，可能导致取数失败或访问错误数据源。  
  - **建议**：禁止硬编码默认 ID，应在无法确定数据源时抛出业务异常，提示用户配置缺失。

-【中】[FusionAlgoInstanceServiceImpl.java: benchmarkFetchTdbDataAsync/约行 2010-2025]  
  非 `JsTdbDataSourceStrategy` 分支中，`fetchTimeAccumulatedMs = System.currentTimeMillis() - overallStart;`。  
  - **影响**：该值被赋为物理总墙上时间，但 JsTdb 分支中 `fetchTimeAccumulatedMs` 是各任务 `rawRes[0]` 的累加纯 API 耗时，两者口径不一致。前端会将其展示为“多线程累计纯 API 耗时”，导致压测数据不可信。  
  - **建议**：统一两种策略分支的耗时统计口径，或在结果中明确标注指标含义，避免误导用户。

-【低】[FusionAlgoInstanceServiceImpl.java: benchmarkFetchTdbDataAsync/约行 1935]  
  代码中残留调试输出：`System.out.println("11111122222:"+ ForkJoinPool.commonPool().getParallelism());`。  
  - **影响**：生产环境打印无意义调试信息，污染控制台输出，并暴露线程池并行度参数。  
  - **建议**：删除该行，必要时改用 `log.debug`。

-【低】[FusionAlgoInstanceServiceImpl.java: 文件头部 import/约行 40-43]  
  将原来的具体并发包导入（如 `java.util.concurrent.CompletableFuture` 等）替换为通配符导入：`import java.util.concurrent.*;`。  
  - **影响**：降低代码可读性，不符合行业常见的显式导入规范。  
  - **建议**：恢复为显式导入，避免 `*` 通配符。

-【低】[IFusionAlgoInstanceService.java: 新增方法注释/约行 156-176]  
  无 `mergePoints` 参数的重载方法与带 `mergePoints` 参数的方法注释几乎完全相同，未体现参数差异或说明该重载是默认归并模式。  
  - **影响**：接口契约不够清晰，后续维护者难以从注释判断两个方法的区别。  
  - **建议**：简化重载注释，指向主方法或明确标注“默认 mergesPoints=true”。
